# Level 5 development plan

Starpost Signals Level 5 focuses on growth, guided onboarding, verified Testnet usage, feedback-driven iteration, and an ecosystem-ready pitch and demo.

## Delivery gates

1. Ship guided onboarding and privacy-conscious growth telemetry.
2. Run a 10-person pilot and fix transaction blockers plus the highest-priority usability theme.
3. Run a 20-person second wave and ship a second feedback-driven improvement.
4. Complete a final 20-person wave and publish evidence for 50 qualified new users.
5. Publish the pitch deck, demo, README improvement table, and final submission links.

The ten consented Level 4 wallets remain baseline proof. They do not count toward the Level 5 cohort.

## Product boundary

- Continue using the deployed versioned Impact Registry and Escrow contracts.
- Keep contract state authoritative; onboarding and analytics cannot authorize financial actions.
- Store onboarding progress locally without names or emails.
- Keep the raw feedback export private because it connects identity, email, wallet, and transaction data.
- Publish only consented, sanitized evidence and reproducible aggregate verification.
- Never count automated identities, failed transactions, duplicate wallets, or incomplete form submissions.

## Acceptance gates

- Guided onboarding works for supporter, contributor, creator, and reviewer personas.
- Every counted participant has a unique email, wallet, successful approved Testnet transaction, and consented form response.
- At least two post-pilot product changes link authentic feedback to Git commits.
- Public evidence contains no names, emails, secrets, or recovery information.
- CI, frontend, indexer, contracts, and E2E checks are green before the final release.
