# Feedback iteration protocol

## Prioritization

Use this order after each wave:

1. Transaction, security, consent, or data-integrity blockers.
2. A theme mentioned by at least three users or linked to a mean score below 4.0.
3. Remaining themes by frequency, then lowest related rating, then smallest safe implementation effort.

Do not call the pre-campaign onboarding implementation “feedback-driven.” Level 5 feedback-driven claims begin only after authentic Wave 1 responses.

## Required release record

For each of the two feedback releases, record:

| Field | Required evidence |
| --- | --- |
| Wave and sample size | Qualified response count after verification |
| Theme | Anonymized wording and mention count |
| Baseline | Related mean rating or funnel conversion before the change |
| Decision | Why this theme outranked alternatives under the protocol |
| Change | User-visible behavior implemented |
| Tests | Automated and manual scenarios added |
| Commit | Direct `https://github.com/EkinOnat/starpost-signals/commit/<sha>` link |
| Result | Same rating/funnel measure after the release |
